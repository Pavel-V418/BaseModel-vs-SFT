# Spider Expanded v1 — подготовка к публикации

**Статус:** аудит и упаковка подготовлены; исходные байты датасета ещё не опубликованы. Не называйте новый набор точной копией обучающего, пока не сверены SHA-256.

## Что нужно

Восстановить именно сохранённые после обучения `train.jsonl` (8222 строк), `val.jsonl` (300), `test.jsonl` (1034) из исходного Kaggle output / приватного набора данных. В репозитории `data/*` исключён через `.gitignore`. Скрипт `src/data.py --include_others` может создать *новую* сборку, но не гарантирует совпадения со старым разбиением.

## Проверка и подготовка к приватной публикации

```bash
python scripts/audit_expanded_dataset.py --data-dir data --out-dir dataset_release --archive
```

Скрипт проверяет число записей, обязательные поля, отсутствие пересечения SQLite `db_id` между train/val/test, совпадающих записей `(db_id, question, gold_sql)`, формирует SHA-256 и ZIP для **приватной** загрузки. Если обнаружены дубликаты, скрипт остановится: сначала вручную выясните, являются ли они частью исторического тренировочного набора. Нельзя тихо удалять записи и продолжать утверждать идентичность.

Чтобы удостоверить совпадение с обучением, укажите SHA оригинальных файлов:
```bash
python scripts/audit_expanded_dataset.py --data-dir data --out-dir dataset_release --archive \
  --expected-train-sha256 ORIGINAL_TRAIN_SHA256 --expected-val-sha256 ORIGINAL_VAL_SHA256
```

При отсутствии оригинальных SHA отчёт имеет статус `candidate_only`.

## Публикация

После проверки источника данных и условий распространения Spider загрузите ZIP как *приватный* Kaggle Dataset или другой разрешённый артефакт. В GitHub коммитятся только manifest, код и инструкция, а не `data/*.jsonl` и SQLite. Добавьте в README ссылку на опубликованную версию, SHA ZIP и инструкции для воспроизведения.

Важно: Spider 1.0 dev (1034) и опубликованный Spider 1.0 test (2147) — разные тестовые наборы. Не добавляйте их в обучающую часть.
