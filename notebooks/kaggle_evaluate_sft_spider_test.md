# Оценка Qwen2.5 SFT Expanded на Spider 1.0 test в Kaggle

[Ноутбук](kaggle_evaluate_sft_spider_test.ipynb) сравнивает Qwen2.5-0.5B SFT Expanded и Qwen2.5-1.5B SFT Expanded, обученные на 8 222 примерах. Для полного прогона используются 2 147 вопросов и 40 SQLite-баз официального Spider 1.0 test в исходном порядке.

## Запуск

1. В приватный Kaggle Dataset загрузите обновлённый [kaggle_sft_spider_test.py](../src/kaggle_sft_spider_test.py) и оба архива:

   - `results_sft_0.5b_nfull_others_r16_lr1e-4_s42_2ep.zip`
   - `results_sft_1.5b_nfull_others_r16_lr1e-4_s42_2ep.zip`

   Поддерживаются и распакованные Kaggle каталоги `outputs/<run>/final`, содержащие `adapter_config.json` и `adapter_model.safetensors`. Для каждой модели нужна одна копия входа. Скрипт проверяет SHA‑256 весов и конфигурации, идентификатор исходной модели и параметры LoRA.

2. Импортируйте ноутбук и подключите Dataset через **Add Input**. Включите **GPU T4** и **Internet**. При выборе T4 ×2 скрипт видит одну карту. Интернет нужен для исходников GitHub, зависимостей и весов Hugging Face. Ноутбук автоматически скачает `spider_data.zip`. Можно также приложить исходный ZIP как отдельный вход. Если Kaggle автоматически распаковывает файл, загрузите его внутри внешнего ZIP, чтобы сохранить исходный `spider_data.zip` для проверки SHA‑256. [Документация Kaggle](https://www.kaggle.com/docs/notebooks)

3. Выполните ячейки сверху до конца раздела **Smoke**. Подготовка сверяет архив и SHA‑256 подготовленных промптов с прогоном команды, проверяет все 2 147 эталонных SQL и запускает `PRAGMA quick_check` на 40 базах. Smoke использует первые 24 вопроса для обеих моделей, показывает свободную видеопамять и сохраняет результаты в `/kaggle/working/sft_spider_test/expanded_v3/smoke/`. Для необязательной CPU-сверки с опубликованными ответами установите `RUN_REFERENCE_AUDIT = True` в первой ячейке и выполните ячейку подготовки.

4. После smoke установите `RUN_FULL = True` в последней ячейке и выполните её. Для запуска полного прогона с сохранением версии можно выбрать **Save Version → Save & Run All** с тем же `RUN_FULL = True`. Результаты сохраняются в `/kaggle/working/sft_spider_test/expanded_v3/full/`. При завершении скачайте с вкладки **Output** пять файлов:

   - `sft_0.5b_predictions.jsonl` и `sft_0.5b_metrics.json`
   - `sft_1.5b_predictions.jsonl` и `sft_1.5b_metrics.json`
   - `comparison.csv`

   В каждом каталоге дополнительно сохраняются общий `test.jsonl` и `checkpoints/`. Если меняете `RUN_NAME`, подставьте его вместо `expanded_v3` в путях.

## Возобновление

Скрипт атомарно сохраняет прогресс после каждых 128 вопросов и после последнего блока. В текущей сессии повторно выполните ячейку Full с тем же `RUN_NAME`. В новой сессии подключите ранее сохранённый Output или приватный Dataset с копией каталога `full`, укажите его абсолютный путь в `RESUME_FROM` и выполните ячейки снова. Для возобновления нужны контрольные точки v3 с теми же моделями, данными, кодом и версиями окружения, включая SQLite и PyTorch. Если прервалась вся сессия, восстановить можно только контрольные точки из уже сохранённой или скачанной копии `checkpoints/`.

## Сопоставимость

Используется оценщик v3 из коммита `1bf6018f71a58551ca6f66077c7a1839a68f1f88` ветки участника №2. В v3 обновлён парсер SQL и исправлено декодирование текста в SQLite. Обе модели используют исходный zero-shot промпт и токенизатор из зафиксированной ревизии Qwen, как в опубликованном прогоне. Генерация greedy (`do_sample=False`, `num_beams=1`), 256 новых токенов, batch size 16, левый padding, seed 42. SQLite открывается только на чтение с лимитом 5 секунд на запрос. Ревизия базовой Qwen2.5-1.5B зафиксирована для повторяемости. В конфигурации обученного адаптера исходная ревизия отсутствует. [Опубликованный замер команды](https://github.com/Pavel-V418/BaseModel-vs-SFT/blob/1bf6018f71a58551ca6f66077c7a1839a68f1f88/results/spider_test/README.md)

Метрики сохранены в долях от 0 до 1. JSON включает Execution Accuracy, Exact Match, Valid SQL Rate, Stop Rate и разбивку по сложности. Время инференса охватывает токенизацию, генерацию и декодирование после загрузки модели. JSONL содержит `db_id`, вопрос, `raw_output`, предсказанный и эталонный SQL, флаги и категорию ошибки.

Transformers, PEFT, Accelerate и PyYAML зафиксированы на версиях опубликованного прогона. PEFT 0.18.0 читает обе конфигурации из архивов и предупреждает о пяти полях более новой версии. Во входных конфигурациях все пять полей имеют значение `null`. Ноутбук берёт PyTorch и SQLite из среды Kaggle и записывает их версии в JSON метрик.

Ориентир 0.5B — **994/2 147 (46,30%)**. Опубликованный пересчёт сохранённых ответов оценщиком v3 подтвердил этот показатель. В новом полном прогоне `published_reference` покажет различия в исходном тексте, извлечённом SQL и флагах. Разный SQL при одинаковом исходном ответе указывает на этап парсинга. Разная оценка при одинаковом SQL указывает на этап исполнения, где следует сверить SQLite и таймауты. При отличиях исходного ответа можно сопоставить записанные версии PyTorch, ревизию модели и настройки генерации. Результат CPU-проверки относится к сохранённым ответам команды.
