# BaseModel-vs-SFT — результаты сравнения моделей на Spider 1.0

**Дата составления:** 24 ноября 2026 г.  
**Проект:** BaseModel-vs-SFT (Text-to-SQL, Qwen2.5)  
**Область отчёта:** (1) Base vs SFT для Qwen2.5-0.5B; (2) влияние размера модели: SFT 0.5B vs SFT 1.5B.  
**Статус:** результаты состоявшихся экспериментов; измерений 3B в данном отчёте нет.

## 1. Постановка эксперимента и данные

Модели получают вопрос на естественном языке и описание схемы базы данных, после чего генерируют SQL. Результат оценивается на SQLite-базах Spider 1.0.

- **Spider dev:** 1034 вопроса — внутренняя проверочная выборка проекта.
- **Spider test:** 2147 вопросов из 40 тестовых баз — основной набор для сравнения.
- **Обучение SFT original:** 6563 обучающих примера из основной части Spider после подготовки.
- **Обучение SFT expanded:** 8222 примера: те же 6563 плюс 1659 из официального `train_others.json`.
- **Validation при обучении:** 300 отобранных примеров; подготовленный исходный validation-сплит содержал 434 записи.
- Для сравнения размеров использованы **две обученные Base-модели с LoRA** на expanded-выборке: Qwen2.5-0.5B и Qwen2.5-1.5B.

**Важно о метриках:** *проектная Execution Accuracy* сравнивает результаты исполнения SQL по правилам `src.evaluate`. *Spider legacy Execution Accuracy* и *официальный структурный Exact Match* рассчитаны отдельно участником №2 для сравнений 0.5B. *Test Suite Accuracy* с дополнительными тестовыми базами в этих результатах отсутствует. Для 1.5B пока доступны **только проектные метрики v3**, а не официальный legacy-результат.

## 2. Сравнение Base vs SFT: Qwen2.5-0.5B

### 2.1. Проектная Execution Accuracy

| Конфигурация | Spider dev, 1034 | Spider test, 2147 |
|---|---:|---:|
| Qwen2.5-0.5B Base, zero-shot | 24,56% | 22,08% (474/2147) |
| Qwen2.5-0.5B Base, 4-shot | 20,21% | 18,07% (388/2147) |
| Qwen2.5-0.5B-Instruct, zero-shot | 23,31% | 24,64% (529/2147) |
| **0.5B SFT original, zero-shot** | **49,42%** | **50,95% (1094/2147)** |
| **0.5B SFT expanded, zero-shot** | **48,65%** | **46,30% (994/2147)** |

На основном test относительно Base zero-shot:

- **SFT original:** +28,88 процентного пункта (50,95% − 22,08%; 620 дополнительных правильных ответов).
- **SFT expanded:** +24,22 процентного пункта (46,30% − 22,08%; 520 дополнительных правильных ответов).
- **Expanded уступает original:** −4,66 процентного пункта по проектной Execution Accuracy (точная разница по долям). Следовательно, добавление 1659 примеров не обеспечило улучшения в данном запуске 0.5B.

### 2.2. Официальные исторические метрики Spider на test

| Конфигурация | Spider legacy Execution Accuracy | Официальный структурный Exact Match |
|---|---:|---:|
| Base zero-shot | 18,40% | 16,58% |
| Base 4-shot | 15,88% | 14,44% |
| Instruct zero-shot | 12,34% | 10,43% |
| **SFT original** | **51,79%** | **47,04%** |
| **SFT expanded** | **46,67%** | **42,43%** |

**Интерпретация:** и проектная, и официальная legacy-метрика подтверждают существенное преимущество SFT над Base. Но эти метрики используют разные правила зачёта; смешивать их значения в одной шкале сравнения нельзя. Официальная *Test Suite Accuracy* не рассчитана.

### 2.3. Особенности сравнения

- Общий тестовый набор, фиксированные промпты, greedy decoding (`do_sample=False`, `num_beams=1`), `max_new_tokens=256`, `seed=42`, левый padding.
- Модель Instruct тестировалась с её штатным chat template, поэтому она является отдельным baseline, а не строго идентичной Base по формату входа.
- Base 4-shot в этой конкретной конфигурации показала результат хуже zero-shot; её Stop Rate на test составил лишь 1,35%, что было отдельно проанализировано участником №2.
- Для обеих SFT сравнение original vs expanded нельзя трактовать как полностью изолированный эффект дополнительных данных без учёта выбора чекпоинта и числа оптимизационных шагов.

## 3. Сравнение двух размеров SFT: 0.5B vs 1.5B

**Источник:** загруженный архив `results.zip`, папка `sft_spider_test/expanded_v3/full/`. Обе модели обучены на expanded Spider (8222 train) и оценены на **одних и тех же 2147** вопросах Spider test.

### 3.1. Итоговые метрики (проектный оценщик v3)

| Метрика | SFT 0.5B expanded | SFT 1.5B expanded | Разница |
|---|---:|---:|---:|
| **Execution Accuracy** | **46,30%** (994/2147) | **61,57%** (1322/2147) | **+15,28 п. п.** |
| Текстовый Exact Match | 32,60% | 39,96% | +7,36 п. п. |
| Valid SQL Rate | 70,84% | 84,21% | +13,37 п. п. |
| Stop Rate | 99,58% | 99,86% | +0,28 п. п. |

Увеличение параметров с 0.5B до 1.5B при одинаковых расширенных обучающих данных сопровождается заметным приростом качества по всем основным проектным метрикам. Это **разница измеренных результатов**, а не оценка статистической значимости или доказательство чисто причинного влияния размера модели.

### 3.2. Качество в зависимости от сложности SQL

| Уровень сложности | Число вопросов | SFT 0.5B | SFT 1.5B | Прирост |
|---|---:|---:|---:|---:|
| Easy | 470 | 74,26% | 81,70% | +7,45 п. п. |
| Medium | 857 | 46,44% | 61,84% | +15,40 п. п. |
| Hard | 463 | 35,64% | 54,64% | +19,01 п. п. |
| Extra | 357 | 22,97% | 43,42% | +20,45 п. п. |

Самые крупные абсолютные улучшения приходятся на сложные запросы **Hard** и **Extra**.

### 3.3. Попарное сравнение на тех же вопросах

| Исход для одного вопроса | Количество |
|---|---:|
| Обе модели ответили правильно | 907 |
| Только 0.5B ответила правильно | 87 |
| Только 1.5B ответила правильно | 415 |
| Обе модели ошиблись | 738 |
| **Итого** | **2147** |

1.5B исправляет существенно больше ошибок 0.5B, чем допускает новых: **415 против 87**. Чистый прирост — **328 дополнительных верных ответов**.

### 3.4. Воспроизводимость и параметры оценки

Внутри `results.zip` проверены оба JSONL предсказаний и оба JSON метрик:

- По **2147** предсказаний на модель; ID, эталонные SQL и сложность вопросов совпадают в одинаковом порядке.
- SHA-256 предсказаний соответствует значениям в JSON метрик.
- **Оценщик:** версия 3; `source_commit=1bf6018f71a58551ca6f66077c7a1839a68f1f88`.
- **Набор:** `Spider 1.0 test`, SHA-256 подготовленных данных `29d5638dbe53dd36b24ddef2384b7a365f2af65c085d044ab7b032f4c1bdcf06`.
- **Генерация:** greedy, `num_beams=1`, `max_new_tokens=256`, batch 16, левый padding, `seed=42`, FP16.
- **GPU:** Tesla T4; обе модели оценивались с одним `runner_sha256`.
- **Время генерации** на 2147 вопросах: 0.5B — **637,9 с (~10 мин 38 с)**; 1.5B — **760,6 с (~12 мин 41 с)**. Это время *инференса*, не обучения.

Контрольные суммы адаптеров (весов LoRA):

| Модель | SHA-256 адаптера |
|---|---|
| SFT 0.5B expanded | `bd31c75f5d4e9adb470b9d3eed60fc935269b98982264a4363934c9976a7b9cd` |
| SFT 1.5B expanded | `22274ed0c15d8ac73f1b4a03566579b63d3cc1da315fc1c09c321f95767e9517` |

### 3.5. Ограничения

- **61,57% у 1.5B — проектная Execution Accuracy, не официальная Spider legacy.** Для прямого сравнения по официальному протоколу нужно дополнительно оценить сохранённые `raw_output`/`pred_sql` официальным скриптом. Заново генерировать SQL для этого не требуется.
- Оценка проведена на одной фиксированной тестовой выборке без нескольких независимых обучений с разными seed.
- Для строгого вывода о влиянии количества параметров дополнительно желательно подтвердить полностью сопоставимые настройки SFT и выбор чекпоинтов.

## 4. Сводный результат и выводы

**Эксперимент 1 — Base vs SFT.** Дообучение Qwen2.5-0.5B существенно улучшило генерацию SQL: с **22,08%** у Base до **46,30%** у expanded SFT или **50,95%** у original SFT по проектной Execution Accuracy на 2147 вопросах Spider test.

**Эксперимент 2 — влияние размера модели.** На общем expanded Spider при одинаковой проектной оценке v3 модель **Qwen2.5-1.5B SFT** достигла **61,57%** против **46,30%** у **Qwen2.5-0.5B SFT**: улучшение **15,28 процентного пункта**, наиболее выраженное на Hard/Extra.

**Следующий шаг:** оценить 1.5B официальной Spider legacy Execution Accuracy, затем обучить и оценить Qwen2.5-3B на том же наборе данных. Это позволит расширить эксперимент на три размера модели.
